# 現代日本の郊外 プロシージャル生成

シードから現代日本の郊外の街を丸ごと生成し、Three.js で描画するデモアプリ。
戸建て・アパート・マンションに加え、駅前の商店街（店舗併用住宅・雑居ビル）、
幹線沿いのコンビニ、町外れの工業団地まで、**用途地域ごとに違う街**を生成する。

```bash
npm install
npm run dev        # http://127.0.0.1:5173
```

`npm run typecheck` / `npm run test` / `npm run build` / `npm run shot`

**操作**: 左ドラッグ=回転、ホイール=ズーム、右ドラッグ=パン。
`W` で**歩行モード**（WASD + Shift、`Esc` で解除）、`C` で**走行モード**
（W/S=アクセル・ブレーキ、A/D=ハンドル、Shift=速度上限アップ、Space=急制動、
`Esc` で解除）。開発ビルドの右上に lil-gui のパラメータパネルが出る。

デバッグ表示に用途地域・用途の塗り分け、道路の占有面（舗装／道路用地）、
未利用地の理由別塗り分けあり。

```bash
npm run shot -- --zones commercial,industrial --kinds konbini,factory
```

## 設計の中核となる判断

- **法規を幾何制約として実装する。** 建ぺい率・容積率・接道義務（4m道路に2m）・
  北側斜線・道路斜線・910mmモジュール。日本らしいシルエットは描くのではなく
  これらの制約から自動的に出てくる。
- **フットプリント = 矩形の塊を建築可能領域でクリップしたもの**
  （`building/footprint.ts` の `fitFootprint`）。四角形以外の敷地にも自然に
  収まる。全建物の約25%が敷地形状で実際に切り欠かれている。
- **三角地では逆に、建築可能領域そのものを外形にする**（`conformFootprint`）。
  楔形の敷地では矩形合成が原理的に破綻するため、最大内接矩形が
  `conformFillThreshold`(0.62) を割ったら建築可能領域を直接採用し、隅切りで
  面取りする。矩形が無いので屋根は陸屋根か片流れのみ。
- **街には歴史がある。** 駅前と外縁を同じ規則で同時に置くと年齢が消える。
  Tier-1 は駅から**育て**（`growth.steps` が街の年齢）、中心は密に、外縁は
  粗く、分譲地の一部は未売却のまま残す。
- **土地は平らではない。** 起伏20〜30mの丘陵、谷を流れる川、段丘崖。道は
  土工量最小の線を選んで丘を巻き、敷地は蹴上げに量子化した平坦面に造成し
  擁壁で留める。
- **直線骨格（straight skeleton）は使わない。** フットプリントを「向きの
  揃った矩形の集合」として作り、屋根は矩形ごとに生成して相互貫入させる。
  凹頂点の split event 等のリスクが構造的に消える。屋根の矩形は面を
  過不足なく覆うことを `test/buildings.test.ts` が検証する。
- **用途地域は「塗る」、用途は「導出する」。** 敷地ごとに閾値判定すると工業が
  胡椒粒になる。地区単位でフラッドフィルして工業を連続区域として塗り、
  その中で既存の幾何ゲート（面積・接道長）を効かせる。用途地域だけは
  道路生成の中（`generateRoads` 内）で決まる ——下流が上流に手を伸ばす唯一の箇所。
- **斜線制限は階数の違いで表現する。** 建物平面を1〜3個の**スタック**に分け、
  北側斜線が効く部分だけ階数を落として陸屋根＋パラペットの屋上テラスにする。
  スタックの和は常にフットプリントと厳密に一致する。

## パイプライン

```
seed
 ├─ terrain/Terrain.ts    丘陵の高さ場（4m格子）＋川の谷＋段丘崖
 │  terrain/Obstacles.ts  勾配・渡河・崖の横断を測る
 └─ city/RoadGrowth.ts    駅から Tier-1 を育てる（成長OFFなら一発生成）
    │  city/RoadDistricts.ts 骨格グラフの有界面 = 地区
    │  city/LandUse.ts       地区ごとに用途地域を割り当てる
    │  city/RoadGrid.ts      地区ごとに自前の直交格子
    │  city/RoadClearance.ts 非接続な道路どうしの間隔を実測し違反を削除
    │  city/Roads.ts         オーケストレーション → 平面化
    │  city/RoadProfile.ts   ノードごとに設計高を解く
    └─ city/Blocks.ts 平面グラフの最小閉路 → 街区ポリゴン
       └─ city/Lots.ts   街路に直交してスライス → 私道・旗竿地
          │  city/RoadSurface.ts 道路の占有面（舗装／道路用地）の唯一の定義
          │  city/LandLoss.ts    敷地にならなかった土地を理由付きで記録
          └─ city/Zoning.ts  urbanity場 + 幾何ゲート → 用途と分譲地クラスタ
             ├─ city/Platform.ts 敷地ごとに造成面 padY と擁壁
             └─ building/    envelope → footprint → mass → roof → facade → details
                └─ build/    チャンク×マテリアル系統でマージ
```

### 道路網
実際の郊外は**区画整理された地区のパッチワーク**——地区内部はきれいな直交格子、
隣とは幹線沿いでだけ角度がずれる。街は駅の十字から**育ち**（`RoadGrowth.ts`）、
外へ行くほど遅く粗くなる。

```
0. 駅  1. 種（幹線の十字） 2. 成長×steps 3. 埋め（穴を潰す）
4. 閉合 5. 地区分割 6. 地区内格子 7. クリアランス
```

- `steps` は**時計**であって第二のシードではない。フロンティア半径は
  `extent · (step / fullAt)^spreadExponent` —— `fullAt` を基準にするので
  年齢を上げても若い街の道はそのまま古い街に残る（`test/growth.test.ts`）。
- 中心が密になるレバーは4つ: Tier-1間隔・地区内格子間隔（世代で決定）・
  未分譲率・urbanity場。密度は**延床面積**で測る（敷地面積比では外縁の方が
  密に出てしまう）。
- 候補道は**土工量**で選ぶ（勾配だけでは丘を登る道と巻く道が同点になる）。
  勾配判定は端点間で行う（局所最大だと候補が壊滅する）。
- Tier-1は折れ線（1区間ごとに折れ角コスト）、輪を閉じ、閉じられなかった
  Tier-1は刈る。半径は Chebyshev で測る（正方形の街の四隅を切り捨てない）。
- `RoadClearance.ts` が非接続な道路どうしの間隔・鋭角交差をスパン単位で検出・削除。
  交差点はマスクして誤検出を避ける。生成方式から独立でテスト可能。
- `layout: 'grid'`（区画整理済み計画住宅地）は成長を切り、地区自身の格子線に
  道路の格を割り当てる。`district`（既定）は成長でTier-1を置く。

### 建物と敷地
- **空き地は理由付きで記録**（`VacancyReason`: `no-buildable-area` /
  `buildable-too-small` / `no-footprint-fits` / `too-narrow` / `not-attempted` /
  `not-yet-developed`）。数え方は**3分割**する：
  - `UNSOLD_VACANCY`（未分譲）——土地は健全、買い手待ち。**街を歳取らせれば建つ**
  - `UNBUILDABLE_VACANCY`（`too-narrow`/`buildable-too-small`）——何年経っても建たない
  - 残り（要調査）——ジェネレータの失敗。0であるべき

  「やむを得ない」1本にまとめると、この2つの正反対の事実が同じ数字に混ざる。
  デバッグ表示も3レイヤー（砂色・灰・赤）に分ける。フィット失敗はセットバックと
  最小床面積を段階的に緩める譲歩（`Builder.ts` の `CONCESSIONS`）で減らす。
- **未分譲は「いつ分譲したか」ではなく「分譲してから何年経ったか」で決まる**
  （`unsoldChance`）。以前は世代だけを見ていて現在に一切言及しなかったため、
  街の年齢（`steps`＝この機能唯一の主要コントロール）が未分譲率に**何の影響も
  与えなかった**——スライダーを最大まで回した完成した街が、途中の街と全く同じ
  割合で外縁を空けたままだった。`fringeVacancy`（既定0.25）は**新規分譲地**の
  割合、`sellOutSteps`（既定12）で完売までの年数。実測: steps=16で21%、
  既定の24で5.0%、30以上で0%。道路も区画も動かない——歳を取ると売れるだけ。
  （`lotScaleForGeneration` が使う `generationAge` は逆に「当時の分譲水準」なので
  現在を見ないのが正しい。同じ数を使い回していたのが混同の元だった。）
- **敷地にならなかった土地も理由付きで記録**（`city/LandLoss.ts` の
  `LandLossReason`）。`VacancyReason` の一段上流にあたる——あちらは「敷地に
  なったが建たなかった」、こちらは「そもそも敷地にならなかった」。分割の各段は
  ポリゴンを `continue` で黙って捨てており、街区に空いた穴を見ても
  **ジェネレータが何かを決めた結果なのか、単に見失ったのかが区別できなかった**。
  `auditLand` が街区から順に道路用地・敷地・記録済みの損失を差し引き、
  残りを `unaccounted` とする——**0であるべき数字**であり、計装漏れの在り処。
  既定シードで街区372,803m²のうち 敷地283,216 / 道路82,666 / 未利用6,921、
  うち理由不明277m²（0.07%）。作業前は 敷地247,633・未利用40,179・理由不明
  23,382m²（6.7%）だった。`test/landloss.test.ts` が見張る。
- **道路の占有面はひとつの定義から引く**（`city/RoadSurface.ts`）。以前は
  描画・敷地の後退・最終検査・テスト2本で**5回**書かれていて半幅が三通りあった。
  形は2つあり、混ぜてはいけない: *舗装*（交差点で0.9半幅ぶんはみ出す。行き止まり
  では出さない）と*道路用地*（側溝ぶん広く、両端をはみ出す）。デバッグ表示は
  この2枚を重ねて出す——**橙が灰から食み出す幅が0.5mなら正常、数mなら街区が
  余計に削られており、灰の無い橙は無い道路のための後退**。街区どうしの隙間が
  「道路が細い」のか「敷地が下がりすぎ」なのかは、これを見ないと区別できない。
- **街区の面は道路中心線で囲まれる——例外なく**。過大街区に私道を通す
  `splitOversized` だけがこれを破って断片を3m内側に削っており、`Lots` が
  そこからさらに3m下げていた。同じ用地を二度引いた結果、私道1本ごとに
  片側3mの死んだ帯が残っていた。私道が作られなかった場合も削るので、
  道路の無い6m幅の空白も生んでいた。
- **接道行は、自分が面している街路の長さより長くなれない。** これが敷地分割で
  一番効く一文で、二箇所に効く。
  - **帯（band）の生成**: 帯は `f.inward` に垂直な半平面2枚の交差で作られており、
    街路方向には**無制限だった**。曲がった街区では一番広い道の帯が自分の
    車道の端を20m越えて街区を薙ぎ、そこを街路に直交してスライスしていた。
    しかも切り取った帯は `consumed` に入るので、本来その土地を受け持つ
    角の向こうの街路からも取り上げていた。`±f.dir` の2枚を足して閉じる。
  - **吸収（`absorbIntoRow`）**: 判定は「union が単一の単純リング」「面積が和に
    一致」だけで、**L 字が素通りしていた**。`sliceStripIntoLots` は L 全体の
    範囲を測って切るので、行の街路長から横にはみ出した部分のスライスは
    街路辺を1本も持たない。行が実際に接している区間（`Row.span`）に
    クリップしてから吸わせる。**余裕は0**——敷地1枚ぶん許すと、吸収する行の
    両端に袋地が1枚ずつ戻ってくる。
- **`FrontRef` はストリップと同じだけ端を延長する**。道路用地のストリップは
  両端を `幅/2+側溝` はみ出させて土地を削るのに、同じ数から作る接道参照線は
  節点で止まっていた。`computeFrontages` は参照線を**線分**として測るので、
  削られたぶんだけ「街路から離れている」と判定され、街区の角と行き止まりの
  頭で幅2.9m（局所街路）〜7m（幹線）の帯が接道を失っていた。
- **街区コアは必ず誰かの土地になる**。`flagLotChance`(0.55) は以前
  「旗竿地にするか**消すか**」を決めていた——街区の奥の土地は五分五分より悪い
  確率で存在しなくなり、私道の奥の奥は必ず消えた。工業地域は
  `flagLotChance: 0` を「私道も旗竿も作るな」の意味で設定しているので、
  コアを全部失っていた。今は「旗竿地にするか**接道行の奥行きに吸わせるか**」を
  決める。
- **どの行も届かない土地は、強引に旗竿地にする**（`forceFlagLots`）。行が
  自分の街路の長さぶんしか土地を取れない以上、深い街区には必ず余りが出る。
  100m²（`SALVAGE_MIN_AREA`）以上なら**面する街路に沿って**body に割り
  （最長辺で割ると隣の敷地を掘って出る竿ができる）、body ごとに竿を通す。
  竿は `placePole` が一箇所で作り、`carveOuts`（他の竿**と街区の私道**）を
  渡されて重複を避ける。これより小さい端切れは `stranded-too-small` として
  **意図的に**捨てる——2.6mの竿を引いた残りは建たない `too-narrow` になるだけで、
  空き地を1枚増やすのは改善ではない。この理由は `block-undeveloped` と同じく
  「決定」の側に分類し、`core-abandoned`（救済を試みて失敗＝欠陥）と混ぜない。
- **敷地は公道を含まない**ことを `Lots.ts` の `clipToRoads` で最後に一括検査
  （上流の各段が個別に静かに失敗しうるため）。行き止まり街路は街区の内側
  扱いで両側を接道として使う。
- **川と段丘崖は「面」なので面として引く**。以前は敷地の重心1点で判定しており、
  崖が角をかすめただけの敷地が丸ごと消え、崖が真ん中を横切る敷地は丸ごと残った。
  消えた土地は記録も残らない——これが「斜面だから空き地」の正体で、未利用地の
  最大分類だった。今は崖・水域を差し引いて残りを敷地として再投入する（接道も
  再計算されるので、崖に切り離された断片は正直に `no-frontage` で落ちる）。
  勾配だけは面ではなく場なので `minBuildableFraction`（既定0.35）で測る。
- **針・廊下状フットプリントは `trimSharpCorners` で刈る**——45°より鋭い凸頂点を
  頂点手術で引っ込める。幅の下限は2.7モジュール(2.46m)。掃除してからクリップ
  する順序が重要。最後の砦 `NEEDLE_FLOOR` は刈り取り角と揃えて40°
  （25°のままだと刈り取りが諦めた28.8°の針が素通りする）。
- **過大敷地の再分割は接道辺を横切って切る**（`resliceOversized`）。OBBの長辺で
  切ると、奥行きのある敷地は**自分の街路と平行に**割られて後背が袋地になる。
- **玄関は建物ごとに1枚の壁を選ぶ**（`chooseEntrance`）。`aim`（道路/駐車場に
  向いている）で候補を絞り、`reach`（街路に近い）で同点を割る。
- **敷地分割は再帰OBBを使わない**——landlocked区画ができ、接道義務を満たさない
  土地には建てられないため。接道辺からリングを剥がし街路に直交してスライスし、
  コアには私道か旗竿地を出す。生存した敷地は全て接道する
  （`test/lots.test.ts`）。端切れも `minLotArea`/`minFrontage`/`minInscribedRadius`
  を満たせば残す。

## 地形・造成

- 高さ場は**4m格子にキャッシュ**（解析関数ではない）。地面メッシュが格子
  そのものの三角形分割になるので問い合わせと描画がずれない。`FLAT_TERRAIN`
  は全部ゼロを返すオブジェクトで、平地モードに特別扱いを要らなくする。
- 川は最後（段丘を足した後）に彫り、河床は単調非増加に強制する。断面は
  水路・深さ（頂点カラー）・乾いた河川敷・護岸の4部分で構成し、護岸の高さは
  地形ではなく設計値から取る。池は作らない（穴は建物に消される）。
- 段丘崖は川の中心線をオフセットして作り、帯幅は格子1セルに固定（45°）。
- `terrain/Graded.ts` が道路・造成面の下の地面を**下げるだけ**（上げると
  擁壁が埋まる）。結果は `Terrain` に戻さない（循環を避ける）。
- 道路は**設計縦断**を持つ（`RoadProfile.ts`）。ノードごとにガウス・ザイデルで
  解く（辺ごとだと交差点が裂ける）。副作用で坂道沿いの敷地列が接道高さの
  階段をタダで受け取る。
- **私道も自前の縦断を持つ**（`solveLaneProfiles`）。私道は道路グラフのノードを
  持たないため縦断解に入らず、以前は両端を「40m以内の道路の高さ」で決めて
  一枚の平面で描いていた——坂では街区の反対側の街路の高さを借りることになり、
  既定シードで47本中34本が地面より1m以上、最悪7m下に潜っていた。私道は
  整地されない（`SMOOTHING.private`）ので**地形に沿わせ**、街路に取り付く
  端だけを数m区間でその高さに寄せ、私道勾配で頭打ちにする。描画も測点ごとの
  リボン連結にする（平面一枚では地形に沿えない）。
- `Graded.ts` の切り下げは**私道の下にも**かける。私道の帯は両側の敷地から
  carve-outされていて、道路でも敷地でもないため誰も掘っていなかった。
  掘り下げが無ければ、縦断を直しても切土区間の私道は丘に埋まったままになる。
- 埋没は `test/slopes.test.ts` の検出器が見張る。判定は**描かれる三角形**に対して
  行う（`GradedGround.heightAt` は `buildTerrainMesh` と同じ対角線で分割する）
  ——バイリニアで測ると、切土の外側に残った1頂点のせいで実際には見えている
  道路まで埋没と報告される。
- 造成面（`city/Platform.ts`）は地面の平均ではなく**接道道路の高さ**に座り、
  蹴上げに量子化する。擁壁の描画は `props/Retaining.ts` に分離。

## 用途地域

地区単位でフラッドフィルし工業を連続区域として塗る（`LandUse.ts`）。安全弁:
種は連結成分から選ぶ（下限を設けると小さい地区が排除され逆効果）、成長に
上限を設ける、商業にも面積の天井を設ける（地区は町が縮んでも小さくならない
ため）。

`extent:320` 実測: 地区数13、最大地区104,676m²（町全体の25%）——判断は
個数ではなく**面積**で行う。「駅から260m以内」のような絶対距離条件は
この粒度では指定できず、代わりに重心距離の下限と商業核隣接からの除外で
表現する。

- 長屋は `setbackScale.side = 0` だけで、建築可能領域からファサードまで
  無料で伝播する。正面だけ0.32mにして道路クリーンアップの許容差と衝突しないようにする。
- 北側斜線は住居系地域にしかかからない（法的事実であり近道ではない）。
- 商店街は「地区」ではなく「通り」の条件（区画の形・幹線接道）で判定する
  —— 用途地域だけを信じると地図の五分の一が商店街になる。

---

## 繰り返しを目立たせない

1. **相関するスタイルベクトル**（`building/style.ts`）: `era`/`wealth`/`formality`
   の3数から20個の外観パラメータを導出。`era`は二峰性分布。
2. **分譲地クラスタ**: 隣接3〜8区画がスタイルベクトルをσ1/6で共有し、
   意図的にほぼ同一の繰り返しを再導入する。
3. **上下階の開口整列**: 上階の開口は80%の確率で下階と同じモジュール位置。
4. **パレット規則**（`material/palettes.ts`）: 屋根/壁の明度差・彩度上限・
   HSVジッタ。屋根色は `buildings.roofHueMix`（既定 赤錆茶22/紺18/銀黒38/
   茶12/青緑10）で設定でき、**系統を先に選んでから系統内で色を引く**
   （後からフィルタをかけると通りやすい色が重みを食い荒らすため）。

---

## その他

- **走行モード**は横移動でなく操舵（速度比例、停止時ゼロ）、速度を持ち越し、
  建物に当たり判定あり（塀・フェンスは通り抜ける）。上限は生活道路で約31km/h、
  Shiftで約58km/h。
- **決定性**: すべての生成関数は `Rng` ではなく**シード文字列**
  （例 `"sakura-3/block/17/lot/4/facade"`）を受け取る。順序非依存で
  1棟だけの再生成やWorker並列化ができる。
- **幾何**: `polygon-clipping` のみに依存し、内側/外側オフセットは自前
  （`geom/offset.ts`）。建物のセットバックは半平面クリップ、街区から道路を
  引く側は実フットプリントの減算（半平面は曲線道路の凹側で破綻するため）。
  `geom/boolean.ts` は戻り値を必ずクリーンアップする。
